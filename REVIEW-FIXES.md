# Исправления по замечаниям ревью

## Задание 1. Потеря региона при 50 000 RPS

**Замечание.** 30 подов на два региона: после отказа одного в оставшемся ≤ 15 подов ≈ 45 000 RPS, в пике часть аукционов останется без ставки.

**Исправление.** RTB-контур рассчитан по принципу N+1 на уровне регионов: **каждый регион постоянно держит 27 подов Bidding** (2 500 RPS/под × 0,8 целевой загрузки → 25 подов + запас, по 9 на AZ), то есть 50 000 RPS + 20% без автоскейлинга в момент аварии. Так же рассчитаны Edge Gateway, Event Collector, Redis и Kafka. Добавлены хронология переключения (≤ 5 мин), метрика мощности региона с алертом и регулярные учения.

## Задание 2. Потеря оплачиваемого показа в Event Collector

**Замечание.** Метка дедупликации ставилась до надёжной записи события: при падении между ними повтор от DSP отбрасывался, показ не попадал в биллинг.

**Исправление.** Порядок изменён на «записать → подтвердить → пометить»: событие публикуется в Kafka с `acks=all`, и только после подтверждения ставится метка в Redis и отправляется ответ DSP. Если Kafka не подтвердила запись, DSP получает `503` без метки и повторяет уведомление. Дубли, возникающие при сбое после записи, отбрасываются потребителями по детерминированному `event_id`, поэтому Redis-метка — лишь оптимизация. Клики пишутся в Kafka или в надёжный локальный журнал (fsync) до редиректа. Добавлены анализ отказов по шагам и сверка для DSP без повторов.

## Задание 3. RPO = 0 для Finance при потере региона

**Замечание.** Синхронные реплики были только в регионе A, реплика в регионе B — асинхронная: проводка, подтверждённая до передачи в регион B, могла исчезнуть.

**Исправление.** Кворумная синхронная репликация `ANY 2 (fin_a2, fin_b1, fin_b2)` (Patroni quorum mode, strict): в кворуме только одна реплика региона A, поэтому каждая подтверждённая транзакция записана на диск минимум одной реплики региона B. Описана процедура до возобновления записи: изоляция старого primary через DCS на трёх площадках (A, B, свидетель C), промоут узла с наибольшим LSN, автоматическая проверка леджера и outbox, продолжение с offset, сохранённых в той же транзакции. Цена (+RTT на `COMMIT`) и поведение при недоступности региона B описаны явно.
